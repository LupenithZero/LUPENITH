# Security Policy

## Current status

This repository currently contains project documents, not a deployed service or software product. There is no dedicated security team and no promise of 24/7 response.

## Reporting a vulnerability

Please do not publish exploitable details, personal data, or sensitive operational information in a public issue. Contact the repository maintainer privately through GitHub and include:

- A concise description of the issue.
- The affected file, service, or version if applicable.
- The likely impact and conditions needed to reproduce it.
- A minimal proof of concept, if safe and necessary.

Do not access, alter, or delete data belonging to others while investigating. Do not use a vulnerability report to threaten, extort, or demand special treatment.

## Response expectations

At this stage, acknowledgement and remediation timelines cannot be guaranteed. If software is later launched, this policy must be revised to state supported versions, private reporting channels, response targets, and coordinated disclosure expectations.

## General security principles

Do not commit passwords, tokens, private keys, personal information, or confidential incident details. Use test data in examples. Review GitHub's repository security features before accepting external code. Security claims must be supported by testing and must accurately state known limitations.
