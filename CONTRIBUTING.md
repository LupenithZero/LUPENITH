# Contributing

Thank you for considering a contribution. This project is early-stage and welcomes careful criticism, including disagreement with its assumptions. You do not need to agree with every long-term goal to help improve an individual document or technical idea.

## Good first contributions

- Point out ambiguity, contradiction, unrealistic assumptions, or missing safeguards in the charter.
- Add high-quality references to claims about science, governance, privacy, or mental health.
- Improve plain-language explanations, accessibility, or translation.
- Suggest a small technical project with a clearly identified user problem.
- Identify an existing open-source project we should learn from or contribute to instead of duplicating.
- Improve the issue templates or contributor workflow.

See [FIRST_TASKS.md](FIRST_TASKS.md) for concrete tasks.

## Before you start

1. Read the [Code of Conduct](CODE_OF_CONDUCT.md).
2. Read the [draft charter](docs/CHARTER.md) and note that it is not yet adopted.
3. Search existing issues and discussions to avoid duplication.
4. For larger changes, open an issue first and explain the problem, alternatives, risks, and expected benefit.
5. Do not post personal, health, financial, location, or other sensitive information in public issues.

## How to contribute

- **Small documentation edits:** open a pull request with a clear summary and reason.
- **Policy changes:** open an issue first, describe the affected rights and possible misuse cases, and invite counterarguments before proposing final wording.
- **Technical project proposals:** state the user problem, existing alternatives, maintenance burden, security implications, license, and the smallest useful milestone.
- **Research references:** link the original source, summarize what it does and does not establish, and distinguish evidence from opinion.

Keep pull requests focused. A small, reviewable change is easier to trust than a large rewrite without discussion.

## Review standards

A contribution is more likely to be accepted when it:

- Improves clarity, usefulness, safety, accessibility, or factual accuracy.
- Respects the protected principles in the draft charter.
- Includes sources for factual claims that need support.
- Considers risks, affected people, alternatives, and possible misuse.
- Does not treat the founder, a majority, an expert, or an AI output as unquestionable.

Maintainers should explain decisions and conflicts of interest. Rejection of a contribution is not a judgment of the contributor's worth or loyalty. Where possible, provide a specific reason and a path to revise.

## Decision status

This repository is not yet governed by a mature elected structure. Until one exists, maintainer decisions are provisional and must be documented. Do not represent repository maintainers as elected leaders of a global organization.

## Licensing

By submitting documentation or other non-code material, you agree that it may be distributed under the repository's stated CC BY-SA 4.0 license unless the contribution clearly states otherwise and maintainers accept that exception. Future code contributions must specify an appropriate open-source license before being merged. Do not submit material you do not have permission to license.

## No unpaid-work assumptions

Contributions are voluntary unless a separate written paid agreement exists. The project does not currently offer employment, compensation, equity, loans, or guaranteed credit beyond maintaining accurate contributor history. Do not make promises on behalf of the project without authorization.
